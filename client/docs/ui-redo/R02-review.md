## 3. 不通过项（要求 Codex 修改）

### 3.1 `--grad-icon-btn-horizontal` 名实不符，基准变体取了少数派

| token | 现值 | 次数 | 节点 |
| --- | --- | ---: | --- |
| `--grad-icon-btn` | `to right` | 46 | 首页页头 magic / settings 等 |
| `--grad-icon-btn-horizontal` | `135deg` | 228 | 其余全部 44×44 图标按钮 |

叫 horizontal 的是斜向 135°，不带后缀的反而是只占 17% 的横向。原因是生成脚本用 `h[0]['x']==0` 判断“横向”，而 135° 的 handle 起点 (0,0) 也满足。后续页面任务按名字取用会拿错。

### 3.2 `-height-48` 两个变体：后缀无意义，角度换算与 grad-card 不一致

- `--grad-primary-height-48`（115°，36 处）与 `--grad-secondary-height-48`（120°，1 处）：同组的基准变体同样是 48 高，后缀区分不了任何东西。
- 115° / 120° 是归一化 handle 空间里的角度，只对正方形元素成立。这 36 个节点宽 143.5–327、高 48，按 Codex 对 grad-card 用的同一算法，实际渲染角度是 144.35°–162.53°（次按钮那一处是 151.00°）。
- 也就是说：grad-card 以“单角度对非正方形是错的”为由拆成 6 个高度变体，主/次按钮却直接用了归一化角度。两种做法只能留一种。

### 3.3 文档结论与数据不符

`R02-result.md`“计划与 JSON 的差异”写“主/次/图标按钮均为 to right”，实际 36 / 1 / 228 处不是。计划 §3.1 把 `grad-icon-btn` 写成“横向（274 处）”也与 JSON 不符（228 处是 135°），应作为差异记录。

### 3.4 修改要求

统一规则：**不带后缀 = 该组出现次数最多的变体；另一个方向用 `-horizontal` 或 `-diagonal`；斜向一律取归一化 handle 角度，不按元素宽高派生变体。**

| token | 值 | 次数 |
| --- | --- | ---: |
| `--grad-primary` | `to right, #BDFF81 0%, #B0FB61 100%` | 62 |
| `--grad-primary-diagonal` | `115deg`，同色标 | 36 |
| `--grad-secondary` | `to right, #1C2223 0%, #171D1E 100%` | 17 |
| `--grad-secondary-diagonal` | `120deg`，同色标 | 1 |
| `--grad-icon-btn` | `135deg, #1B2121 0%, #131818 100%` | 228 |
| `--grad-icon-btn-horizontal` | `to right`，同色标 | 46 |
| `--grad-card` | `145deg, #253229 6.17%, #17221C 93.83%` | 10 |
| `--grad-card-horizontal` | `to right, #253229 0%, #17221C 100%` | 9 |

- 删除 `--grad-card-height-238/258/294/322/341` 与两个 `-height-48`，token 总数 169 → 164，四组计数总和不变。
- 斜向 token 的注释里写明：这是归一化角度，Figma 在非正方形元素上的实际渲染角度随宽高变化，并列出各尺寸的实际角度（主按钮 144.35–162.53°，对话框 140.03–153.00°）作为证据。
- `R02-result.md`：改正 3.3 的那句话；“差异”一节补上主/次/图标按钮三组的拆分说明；文末生成脚本同步更新，保证仍可复现。
- 一并按 §4 第 7 项约掉浮点尾数。

选归一化角度而不是按尺寸派生的理由：对话框和按钮的宽高会随文案（尤其韩文）变化，按高度命名的 token 只对这 6 个高度成立；归一化角度就是原型 CSS 里的源值（现有 `styles.css` 的 `.primary` 正是 `115deg`）；两端色差很小，角度差在截图上看不出来。
