## 3. 不通过项（要求 Codex 修改）

### 3.1 `--grad-icon-btn-horizontal` 名实不符，基准变体取了少数派

| token | 现值 | 次数 | 节点 |
| --- | --- | ---: | --- |
| `--grad-icon-btn` | `to right` | 46 | 首页页头 magic / settings 等 |
| `--grad-icon-btn-horizontal` | `135deg` | 228 | 其余全部 44×44 图标按钮 |

叫 horizontal 的是斜向 135°，不带后缀的反而是只占 17% 的横向。原因是生成脚本用 `h[0]['x']==0` 判断“横向”，而 135° 的 handle 起点 (0,0) 也满足。后续页面任务按名字取用会拿错。

### 3.2 `-height-48` 两个变体：后缀无意义，角度没有按宽高比换算

- `--grad-primary-height-48`（115°，36 处）与 `--grad-secondary-height-48`（120°，1 处）：同组的基准变体同样是 48 高，后缀区分不了任何东西。
- 115° / 120° 是归一化 handle 空间里的角度，只对正方形元素成立。这 37 个节点都不是正方形（宽 143.5–327、高 48），按 Codex 自己对 grad-card 用的算法换算，实际渲染角度是 144.35°–162.53°（次按钮那一处是 151.00°），色标位置也不是 0% / 100%，而是 8.49% / 91.51%（次按钮 7.74% / 92.26%）。
- grad-card 的做法（按 handles 和节点宽高换算，每个尺寸一个变体）是对的，6 个值我重算后全部一致；主/次按钮没有用同一做法，这是要改的地方。
- `--grad-icon-btn` 的 135° 不受影响：228 个节点全部是 44×44 正方形，归一化角度即实际角度。

### 3.3 文档结论与数据不符

`R02-result.md`“计划与 JSON 的差异”写“主/次/图标按钮均为 to right”，实际 36 / 1 / 228 处不是。计划 §3.1 把 `grad-icon-btn` 写成“横向（274 处）”也与 JSON 不符（228 处是 135°），应作为差异记录。

### 3.4 修改要求

命名规则：**不带后缀 = 该组出现次数最多的那个精确值；横向另一个叫 `-horizontal`；斜向叫 `-diagonal`，同一组斜向有多个尺寸时再加变化的那一维（`-w<宽>` 或 `-h<高>`，小数点写成 `-`）。**

换算规则（与 Codex 对 grad-card 已用的算法相同，必须考虑宽高比）：设节点宽高为 w×h，handles 为 h0/h1/h2（归一化坐标）。等色线方向是 `((h2−h0).x·w, (h2−h0).y·h)`，CSS 渐变方向取它的垂线，并取与 `((h1−h0).x·w, (h1−h0).y·h)` 同侧的那个，记单位向量为 `(nx, ny)`；CSS 角度 = `atan2(nx, −ny)`；CSS 渐变线长度 = `|nx|·w + |ny|·h`，把 h0、h1 相对元素中心的位置投影到这条线上得到首尾色标的百分比。归一化角度只在 w = h 时可以直接用。
